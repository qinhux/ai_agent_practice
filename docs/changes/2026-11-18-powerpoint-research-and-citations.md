# PPT 资料搜索与当页引用

生成链路增加：研究决策 → 搜索 → 原文读取 → 证据提取 → 大纲 → 逐页文案与来源标注 → 配图 → 渲染交付。按用户要求已取消独立核验、核验失败拦截和自动改写。

## 配置与模式

- 搜索与网页读取改为 DeepSeek Search & Fetch API，复用已有 `DEEPSEEK_API_KEY`，不向客户端公开。移除示例配置和 Compose 中的 Tavily 密钥项。
- 搜索调用 `POST https://api.deepseek.com/v1/tools/search`，传入 `query`、`count: 4`、`need_content: false`；搜索词最多 128 个 Unicode 字符。读取调用 `POST https://api.deepseek.com/v1/tools/fetch`，传入单个 `url`，使用返回的 Markdown 正文，不回退使用搜索摘要。
- 将搜索结果的 summary/snippet、site_name、date 映射为摘要、发布站点和发布日期；读取成功后优先使用正文页标题。缓存、取消、预算与引用数据结构保持一致，兼容已保存的来源。
- 官方接口的 401、402、403、404、429 错误会提供明确提示，非法返回结构和空正文不能进入证据池。Search 与 Fetch 直接调用按成功请求计费，见 [官方说明](https://api-docs.deepseek.com/guides/search/)。
- `/api/chat` 接受 `researchMode: auto | on | off`，缺省为 `auto`；客户端提供对应选择。
- `off` 在请求层禁止外部搜索；自动模式可在研究失败后转为基于用户材料的内容并给出下载提示；强制联网模式未取得原文时返回明确错误；已读取资料但未提取到可引用片段时继续生成。
- 工具注册表增加 `research` 域，提供 `searchWeb`、`readSource`；PPT 自行执行研究，避免依赖外层 Agent 把网页压缩成无来源的 context。
- 每轮上限为 4 次查询、6 篇原文；仅允许读取本轮真实搜索结果里的来源 ID。每个请求独立缓存，网络调用有超时和取消信号。

## 保存与显示

`Presentation.source.research` 保存来源元数据、有限长度的原文、证据摘录、统计时期和适用范围。`slides[].citations` 保存文本目标、文本快照和证据 ID，随稳定 `slideId` 一起移动。用户材料使用单独类型，并明确注明未经独立核实。兼容没有 research/citations 的历史结构，不需要迁移。

页面引用编号按实际使用的来源生成，同源去重。底部以 10pt 显示简短来源和超链接，完整信息放入演讲者备注。默认模板文字预留引用区，用户自定义文字位置与引用区重叠时给出错误，避免静默覆盖。引用不增加页数。

引用在逐页写作时一起产生，不再额外调用模型检查事实、口径或计算。程序仅检查目标、ID、文本快照和原文摘录的一致性，这不代表事实已经核实。原文读取失败时不会把搜索摘要冒充证据。

## 编辑与验证

样式、位置及页序调整保留引用；正文变化自动清理对应的旧引用，不再调用模型核验或阻止事实修改；删除页面会移除随页引用。保存前再次执行结构和原文一致性检查。

`npm test` 使用现有 TypeScript 编译器及 Node 内置测试框架，无新增依赖。覆盖禁网、密钥缺失、缓存、原文失败、伪造证据、引用校验、编辑事务及导出 PPTX 的链接和备注。可设置 `PPT_RESEARCH_PREVIEW_DIR` 导出测试用 PPTX 进行排版检查。

暂未实现规划后的补充搜索、图片授权检索、用户可选的参考文献附录，以及独立人工或第二数据源核实。

## 工具域在追问中丢失的修复

此前每轮请求仅按最新分类启用工具；分类为空时只暴露 `requestToolDomains`。现在从助手历史中恢复已开启的域和已调用工具对应的域（包括失败操作和旧版 PPT 工具），再合并本轮分类。没有历史域且分类为空或失败时，回退到全部已注册工具。路由仅优化模型上下文，不作为禁止调用工具的边界；是否执行仍由用户任务决定。

跨域提示明确要求先调用 `requestToolDomains`，再继续原任务，不能把暂未启用解释成工具被删除。新增回归测试覆盖空分类、跨轮恢复、失败重试、旧版工具，以及流式的开启域 → 生成 → 完成交付 → 禁用后续工具链路。
